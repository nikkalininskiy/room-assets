## 2. Выбор стека

| Технология | Обоснование |
|------------|-------------|
| **React 19 + TypeScript** | Строгая типизация, компонентный подход, большая экосистема |
| **Vite** | Быстрый дев-сервер, HMR, простая сборка в статику |
| **MUI (Material-UI)** | Готовые компоненты (таблицы, формы, диалоги), иконки, темизация |
| **IndexedDB** | Асинхронное хранилище с транзакциями и индексами (лучше localStorage) |
| **MSW** | Перехват запросов на уровне Service Worker — компоненты не меняются при переходе на реальный API |
| **Vitest** | Быстрые модульные тесты, совместим с Vite |
| **date-fns** | Работа с датами (парсинг, форматирование, сравнение) |
| **Docker** | Кроссплатформенный запуск, изоляция окружения |

### Почему IndexedDB, а не localStorage

- **localStorage** — синхронный, блокирует поток, лимит ~5 МБ
- **IndexedDB** — асинхронный, поддерживает транзакции и индексы, нет жёсткого лимита

## 3. Модель данных

### Room (Аудитория)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор |
| `name` | `string` | Название |
| `capacity` | `number` | Вместимость |
| `features` | `string[]` | Оборудование |

### Asset (Актив)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор |
| `name` | `string` | Название |
| `inventoryCode` | `string` | Инвентарный номер |
| `status` | `"available" \| "in_use" \| "maintenance"` | Статус |

### Booking (Бронь)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `string` | Уникальный идентификатор |
| `resourceType` | `"room" \| "asset"` | Тип ресурса |
| `resourceId` | `string` | ID ресурса |
| `title` | `string` | Название брони |
| `start` | `string` | Начало (ISO 8601, UTC) |
| `end` | `string` | Окончание (ISO 8601, UTC) |
| `notes` | `string?` | Примечание |

## 4. Бизнес-правила

1. **Пересечения броней** — нельзя создать бронь, если для этого же ресурса уже есть бронь на пересекающийся интервал.
2. **Время** — хранится в UTC (ISO 8601), отображается в локальном часовом поясе пользователя.
3. **Валидация** — время начала должно быть меньше времени окончания.

## 5. Проблемы и решения

### Windows

| Проблема | Решение |
|----------|---------|
| Долгая установка пакетов | Использовано зеркало npm |
| Ошибка `EPERM` | Запуск терминала от администратора |
| Ошибка SSL при `git push` | Использован VLESS + Reality (обход фильтрации ТСПУ) |

### Linux (WSL 2)

| Проблема | Решение |
|----------|---------|
| Запуск через Ubuntu | `cd /mnt/c/Users/Admin/room-assets` |
| Установка Node.js | Через `nvm` или `apt` |
| Приложение работает | Скриншот: `docs/linux-run.png` |

### CRLF / LF

- Добавлен `.gitattributes` с `* text=auto` для нормализации концов строк
- Предотвращает конфликты между Windows и Linux

### MUI v7

- Появились предупреждения о `inputProps`, `justifyContent`, `alignItems`
- Решение: перенесены в `slotProps` и `sx`
- На работу не влияют

### Docker + Rolldown / lightningcss

- npm не устанавливал платформенные бинарники для Linux
